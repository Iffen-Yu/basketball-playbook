# 系篮球队战术库

这是一个无需构建工具即可运行的静态网页战术库。

## 本地查看

直接打开 `dist/index.html`，或在 `dist` 目录启动任意静态文件服务器。

## 维护方式

“执行要点”统一保留五条简明提示，每条用“动作主题：具体做法”表达，围绕进攻方的跑位、掩护时机、接应和出球选择。防守位置只作为进攻判断条件，不写防守方的执行建议，也不混入动画实现说明。修改时须同时检查分支的 `coachingPoints`；左右镜像由源战术自动同步。

- 战术内容：`dist/plays.js`
- 左4（破2-3联防）：`dist/plays-left4.js`
- 左2连续弧线与分支节奏：`dist/plays-left2-routes.js`
- 右3（破2-3联防、条件分支）：`dist/plays-right3.js`
- 掩护标记与左右镜像生成：`dist/plays-variants.js`
- 球场尺寸及坐标转换：`dist/court.js`
- 动画与交互：`dist/app.js`
- 分角色时间轴与速度曲线：`dist/motion.js`
- 页面样式：`dist/styles.css`
- 英文战术逐句文本：`dist/i18n-en.js`
- 中英界面、语言偏好与镜像文本：`dist/i18n.js`

导航按2号、3号、4号战术分组，每组展开后选择左侧或右侧版本。六个版本均已录入，目录仅显示战术数量，不再展示完成状态、完成比例或状态绿点。

## 对照学习布局

默认打开“执行要点”，可切换到“分步动作”查看当前动作与步骤列表。桌面端球场与学习区并排，学习区独立滚动；手机端球场随页面吸顶，向下阅读最后一条要点时仍能看到完整球场。球场始终按原比例完整显示，不裁掉底角或单独拉伸。

点击执行要点中的进攻/防守号码，或球场上方1—5号按钮，可高亮定位对应球员；再次点击同一号码或“取消定位”恢复。定位只改变视觉强调，不暂停动画、不改变跑位或球权。切换战术时清除定位，切换分支时同步更新要点。

“查看配合说明”按需展开，避免长简介挤占球场。分支选择仍在到达节点后才出现，位于学习区，不改变球场高度。“执行要点／分步动作”支持左右方向键及Home/End切换；步骤列表支持Enter/空格操作。

已录入左2的盯人挡拆分支及左4的破联防配合。左4采用球队确认的1→4→3传球：两侧无球掩护，2号抄底到右底角，4号外弹接球，3号同步走中路进入罚球线。联防动画展示被抄底牵制、延迟高位扑防的一种示例。可通过 `index.html#left-4` 直接打开左4。

右3按球队确认的2-3联防呈现：1号向右与2号手递手，X1跟球防2号，不追无球1号；4号先站稳卡住右侧下线X3的收缩路线，1号从4号身后溜底进入篮下。弱侧5号快速上提罚球线接2号传球，与篮下1号构成高低位威胁。第一层分支可选择X4护篮下时5号自己攻、X4扑高位时5传1，或篮下没机会继续穿底。第三种情况下1号到3号同侧底角，第二层分支选择5传1或5传3。动画只示范阅读窗口，不预设投射能力或投篮命中。可通过 `index.html#right-3` 直接打开右3。

## 球场比例

按 FIBA 标准半场绘制：15 米宽、14 米长，横纵使用同一比例（60 SVG 单位/米）。底线为 y=0，篮筐中心距底线 1.575 米。三分弧半径 6.75 米；罚球线距底线 5.80 米，罚球半圆半径 1.80 米；禁区宽 4.90 米。线条按 5 厘米宽绘制，尺寸采用线中心近似，边缘偏差不超过 2.5 厘米。

所有球员、篮球和跑位曲线也按米定义，通过 `COURT.point(x, y)` 转成画面坐标；不要单独拉伸球场或某一条弧线。罚球外半圆最远处距底线 7.60 米，三分弧顶距底线 8.325 米，两者之间有约 0.725 米间隔。

尺寸来源：[FIBA 官方规则，第 2 条及球场图](https://assets.fiba.basketball/image/upload/documents-corporate-fiba-official-rules-2024-v10a.pdf)。

## 中英文维护

页头“中文／EN”按钮即时切换全部界面、战术简介、步骤、执行要点、分支及球场提示。切换不重置动作时间、球权、已选分支、节点确认、阅读标签或定位球员。语言选择保存在本机，可通过 `?lang=en#right-3` 或 `?lang=zh#left-4` 分享指定语言与战术；未指定时默认中文或沿用上次选择。

两种语言共用唯一的跑位与速度数据，英文只覆盖文本；左右镜像在文字上同步交换left/right，球员编号、分支ID和动画时间轴保持一致。`i18n-en.js` 以完整中文句子为键，人工维护对应英文；修改中文后必须更新英文键值，新增战术不能依赖术语替换或浏览器自动翻译。

篮球术语已对照FIBA/WABC原文核查：手递手为handoff/dribble handoff，顺下为roll，短角为short corner，高位为high post，快速上提为flash，卡位限制补防为seal，底线跑动为baseline cut，扑防为closeout。左4的掩护是off-ball screen，随后外弹为pop out；不要把这个无球配合误叫成持球挡拆的pick-and-pop。左2的left/right screen保留队内相对叫法，并配合middle/baseline drive说明实际方向。

核查来源：[WABC Level 1教练手册：掩护、roll/pop](https://assets.fiba.basketball/image/upload/documents-corporate-wabc-coaching-level-manuals-level-1-eng.pdf)、[FIBA东京奥运技术报告：DHO、高低位及联防进攻](https://assets.fiba.basketball/image/upload/documents-corporate-studies-and-facts-fiba-scouting-report-olympic-games-tokyo-2020-mens.pdf)、[FIBA Assist 33：short corner及联防掩护](https://d3o24yhvamisba.cloudfront.net/FIBA/pdf/a33.pdf)。

## 动作时序

每步 `duration` 为 1× 下的毫秒数。`motions` 可按球员标签分别编排关键帧：`t` 为本步 0—1 的进度，位置通过 `COURT.point` 转换；重复坐标用于等待或受阻停顿。`easing` 的 `accelerate` / `decelerate` 保留加减速意图，`via` 作为弯曲路线的控制参考；`linear` 和默认值同样参与连续轨迹生成。

引擎按整段战术生成保形三次曲线，相邻关键点和步骤之间共享速度衔接，转弯时不会突然折向或逐段重新起步。停顿仍严格遵守重复关键帧的时段。画出的跑位、运球和传球箭头直接来自同一条实际轨迹；掩护标记和可选传球线单独保留。

`ballOwner` 让篮球跟随持球人，避免球沿直线移动而与运球路线分离。`cues` 指定提示出现的进度范围，路径也可用 `from` / `to` 控制显隐。`option` 路线表示传球选择，不会自动把篮球传出去。

左4的主跑位使用 `routes`：以连续三次贝塞尔弧线定义实际路线，以 `timing` 单独定义沿路线走过的距离。`node` 指弧线端点（起点为0），`progress` 指全程弧长比例；`step` / `t` 指到达时间。重复的距离节点表示站稳等待。引擎按弧长播放，因此转弯不会因为控制点密集而无故减速，跨步骤也不会重新启动；显示的箭头由同一条曲线精确截取得到。2号抄底、3号中路切入连续完成，4号明确保留掩护停顿后外弹。

左4的X2也使用独立连续路线：向3号切入方向横移→在5号身侧受阻→从外线侧绕掩护→沿3号身后追防。蓝色虚线箭头表示追防；重复距离节点保留受阻时间，不能用直接穿过掩护或主动退往篮下代替。

左2的两个分支也使用相同的弧长路线引擎，决策选项的 `routeOverrides` 替换该分支的完整球员轨迹，保留X2受阻、X4先补防、4号再顺下的时序。掩护短线由 `screenActor` 和 `screenNormal` 定义，按当帧站位绘制在球员圆点外侧，仅在掩护有效时显示。

右2、右4由对应左侧战术自动生成，左3由右3自动生成，围绕球场中轴镜像球员、球、曲线控制点、传球选项及提示位置；球偏移与掩护朝向作为向量单独反转。球员号码不变；左挡／右挡的文字和选择ID一起反转，因此右2默认“右挡·走中路”，另一分支“左挡·走底线”。左右战术共用动作时序，不需要分别维护。

暂停保存当前动作时间，继续不会重播路径；播放时更改速度立即生效。拖动“本步进度”可精确观察受阻、补防和顺下的时间差。点击步骤会从该步骤的起始站位重播该段。

## 战术分支

左2在第3步“4号上提”前设置 `screen-direction` 选择：左挡走中路，右挡走底线。“左右”沿用球队相对叫法，以“中路／底线”确认实际方向。

战术的 `decisions` 数组描述选择节点：`atStep` 为从0开始的步骤索引，`defaultOption` 用于预览默认路线，`options` 中的 `stepOverrides` 按步骤索引替换对应动作（含站位、独立速度、提示与路线）。`PlayMotion.resolvePlay` 将选择组合成可播放的路线，不修改原始战术。

3号战术的第二个节点使用 `when: {decision:'high-low-read', option:'continue'}`，只在继续穿底的分支出现。`endStep` 让高位进攻、传篮下两个分支在第7步结束，不会随后无故接上底角动作。切换前一节点会清空后续选择与确认状态；路线时间轴忽略已裁掉的后续步骤。

默认预览不代表已经确认。选择面板随步骤出现：到达第一个决策节点之前完全隐藏，不显示未来节点的选项；到达节点时暂停，选择后继续对应分支。当前节点的选项保留用于重播，直到到达下一个节点才替换，不能提前选择后续分支。回看节点之前的步骤会隐藏对应选择，重置也会收起面板。切换已经播放过的分支会从该节点重新播放。重置保留所选方向，但到达节点后需重新确认。

## 验证与更新

`scripts/check-court.py` 在本机Chrome中检查球场、2/4号战术回归，以及 `scripts/check_right3.py` 提供的3号战术四条分支、球权连续性、动作速度、左右镜像、节点暂停与手机显示。`scripts/check_coaching.py` 检查六个版本及分支共14种组合的执行要点，可用 `--coaching-only` 单独运行。需要Python及websocket-client；Chrome路径可在脚本中调整。

`scripts/check_layout.py` 检查十种桌面、平板和手机尺寸，包括阅读最后一条要点时球场仍可见、号码按钮真实点击、定位状态同步、标签页键盘操作，以及分支出现不挤压球场；可用 `--layout-only` 单独运行。

`scripts/check_i18n.py` 检查全部六个版本、14种分支组合的英文覆盖及中英文动作完全一致，另检查暂停/播放中切换语言、节点确认、语言偏好和30种英文战术/屏幕组合。可用 `--i18n-only` 单独运行；漏翻会使检查失败。

线上更新需提交完整 `dist` 内容，特别是新增的 `plays-right3.js` 及引用它的 `index.html`；仅覆盖旧HTML或遗漏脚本会导致新战术缺失。本地修改不会自动发布到GitHub Pages。
